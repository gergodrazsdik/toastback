# toastback — async Windows toasts with callbacks, for WSL and scripts

> Implementation brief for Claude Code. Target: a working, released v1 in 1–2 days.
> Develop and build in WSL (cross-compile with cargo-xwin), task runner `just`, repo + CI + releases on GitHub.
> Test on the Windows host via WSL interop.

## 1. What it is

`toastback` is a single Windows executable that shows a **toast notification** or a **native dialog**,
described in JSON or quick CLI flags, and **returns immediately**. When the user clicks a button
or the toast body, Windows relaunches `toastback`, which runs the **callback command**
attached to that button. The callback can run in **WSL** (by default in the distro, user and working directory
that sent the notification) or on **Windows**.

```bash
# from WSL
toastback -t "Backup finished" -m "42 GB in 12 min"                  # simple alert
cat ask-deploy.json | toastback                                       # prints the notification id, exits 0
```

## 2. Decisions (locked)

| Topic | Decision |
|---|---|
| Language | Rust, `windows` crate (Microsoft). No runtime deps beyond Windows itself. |
| Target | `x86_64-pc-windows-msvc` only, static CRT. Arm64 later. |
| Build | In WSL via `cargo xwin build`. No Windows dev environment needed. |
| Task runner | `just` (justfile), bash recipes. |
| Execution model | **Async / fire-and-forget.** The caller never waits for user interaction. Exit code = "shown" (0) or "failed to show" (non-zero). stdout = notification id. |
| Interactivity | **Buttons only** (no text/select inputs in v1). |
| Activation | **Protocol activation** via a per-user URI scheme `toastback://` (HKCU). No COM activator. |
| Callbacks | **Per-button `run`** + optional notification-level **`default`** handler. |
| Display modes | `toast` (default) and `dialog` (native TaskDialog). Body click can open a **details dialog**. |
| Repo / CI | **Public** GitHub repo `<owner>/toastback` (owner = `gh api user -q .login`); GitHub Actions builds on Linux with cargo-xwin, smoke-tests on a Windows runner. |
| License | **GPL-3.0-or-later**. `LICENSE` = verbatim text from gnu.org, `license = "GPL-3.0-or-later"` in `Cargo.toml`, `// SPDX-License-Identifier: GPL-3.0-or-later` at the top of each source file. Included in the release zip. |
| CLI parsing | `clap` (derive). Faster to build, good `--help`; binary size cost is acceptable. |
| Rust | Edition 2024, latest stable toolchain (`rust-toolchain.toml` pins channel `stable` + target + rustfmt/clippy). |
| Distribution | **GitHub Releases**: `toastback.exe`, `toastback-x86_64.zip`, `install.sh`, `SHA256SUMS`. No installer/MSI. |
| Installation | **Self-installing exe**: `toastback.exe install` copies itself to `%LOCALAPPDATA%\toastback\bin`, registers HKCU keys and writes the WSL shim. A WSL one-liner (`install.sh`) wraps this. |
| WSL shim | **Generated by the exe** from an embedded template (`toastback.exe shim`), single source of truth. |
| Out of scope v1 | Custom popup, wait mode, inputs, arm64, update/replace-by-id, scheduled reminders, code signing, winget/scoop, self-update. |
| Platform | Windows 10 22H2+ / Windows 11, per-user install, no admin. |

Known limitation (by design): after the sending process exits, Windows does not tell anyone
about **dismissal or timeout**. There is no `on_dismiss`. Only clicks trigger callbacks.

## 3. Architecture

```
WSL bash / pwsh / Task Scheduler
   │  toastback [file|-] | -t/-m flags     (+ context: distro, user, cwd — added by the shim)
   ▼
toastback.exe show
   ├─ parse + validate spec, fill context, copy images to cache
   ├─ write %LOCALAPPDATA%\toastback\pending\<id>.json  (spec + random token)
   ├─ mode=toast  → ToastNotificationManager (registered AUMID), buttons → toastback://act?...
   ├─ mode=dialog → spawn detached `toastback.exe __dialog <id>`, return immediately
   └─ print <id>, exit 0
            ... later, user clicks ...
Windows shell → toastback.exe activate "toastback://act?id=<id>&a=<button>&t=<token>"
   ├─ load pending\<id>.json, verify token (reject otherwise)
   ├─ a=__body & on_click=details → show TaskDialog (details + same buttons) → selected button
   ├─ resolve run: button.run ?? spec.default ?? nothing
   ├─ execute (wsl.exe / Windows process / ShellExecute), hidden window, capture output
   ├─ append to log; if it fails and notify_on_error → small error toast
   └─ remove the toast from Action Center, mark pending as done
```

**One binary, Windows (GUI) subsystem.** No console flash when started by Task Scheduler or by
protocol activation. stdout/stderr still go to the pipes that WSL interop gives it.
→ **Verify in M0.** Fallback: a second console-subsystem binary `toastback-cli.exe` for the CLI path.

### State directory `%LOCALAPPDATA%\toastback\`
- `bin\toastback.exe` — the installed copy. All registration points here, never at a download folder or `\\wsl.localhost` path.
- `install.json` — install record: version, install time, WSL distros that received a shim, PATH change made or not. Used by `uninstall`/`doctor`.
- `pending\<id>.json` — spec + token. Pruned when older than `expires` (default 3 days for toasts, the Windows limit, and 7 for dialogs) on every run.
- `cache\` — icons/images copied from WSL paths (toast images from `\\wsl.localhost` are unreliable).
- `log\toastback.jsonl` — events: shown, activated, callback started/finished (exit code, duration, stdout/stderr tail ≤ 8 KB). Rotate at ~5 MB.

### Security
- Activation URIs carry only `id`, button id and a random per-notification **token** (128 bit, OS RNG) stored in the pending file. Anything that doesn't match is ignored and logged. Commands never come from the URI.
- Context reaches callbacks as **environment variables**, never by interpolating into a command string.

## 4. JSON spec (v1)

```jsonc
{
  "id": "deploy-1234",              // optional; generated (short, sortable) if absent
  "mode": "toast",                  // toast | dialog
  "title": "Deploy to production?",
  "body": "Build 1234 passed all checks.",
  "details": "Long text shown in the details dialog…",   // optional
  "icon": "/home/g/icons/rocket.png",   // Windows or WSL path; copied to cache
  "image": null,                    // optional hero/inline image
  "attribution": "CI",              // small grey line on toasts
  "scenario": "default",            // default | reminder | alarm | urgent  (reminder/alarm stay on screen)
  "sound": "default",               // default | silent | alarm | reminder
  "expires": "3d",                  // how long it lives in Action Center / pending store (toasts: max 3d; dialogs default 7d)
  "on_click": "details",            // details | default | none  (body click). Default: "details" if details set, else "default"
  "buttons": [                      // max 5
    { "id": "deploy", "label": "Deploy", "style": "success",
      "run": { "wsl": "./scripts/deploy.sh --env prod" } },
    { "id": "logs", "label": "Open logs",
      "run": { "open": "https://ci.example.com/build/1234" } },
    { "id": "later", "label": "Not now" }                    // no run → falls back to "default", else just dismisses
  ],
  "default": { "wsl": "echo \"$TOASTBACK_ACTION\" >> ~/toastback-clicks.log" },   // optional default handler
  "data": { "build": 1234 },        // arbitrary JSON passed to callbacks as TOASTBACK_DATA
  "notify_on_error": true,          // error toast if a callback exits non-zero
  "context": {                      // normally filled by the WSL shim / CLI flags
    "distro": "Ubuntu-24.04", "user": "g", "cwd": "/home/g/app"
  }
}
```

### `run` forms (exactly one primary key, plus optional modifiers)
| Form | Meaning |
|---|---|
| `{"wsl": "string"}` | `wsl.exe -d <distro> -u <user> --cd <cwd> -- bash -lc "<string>"` |
| `{"wsl": ["argv", …]}` | `wsl.exe … --exec argv…` (no shell) |
| `{"cmd": "string"}` | `cmd.exe /d /c <string>` |
| `{"pwsh": "string"}` | `pwsh -NoProfile -Command <string>` (falls back to `powershell.exe` if pwsh missing) |
| `{"exe": ["C:\\path\\x.exe", "arg"]}` | `CreateProcessW` directly |
| `{"open": "url-or-path"}` | `ShellExecuteExW` (browser, file, folder) |

Optional modifiers: `"cwd"`, `"env": {}`, `"distro"`, `"user"` (override context), `"timeout": "5m"` (kill after).

### Callback environment
`TOASTBACK_ID`, `TOASTBACK_ACTION` (button id, or `__body`), `TOASTBACK_TITLE`, `TOASTBACK_DATA` (JSON string).
For `wsl` runs these are added to `WSLENV` so they cross into Linux.

### Toast rendering rules
- Build XML with proper escaping (or via `Windows.Data.Xml.Dom` APIs). Never `format!` raw user text into XML.
- Buttons: `activationType="protocol"`, `arguments="toastback://act?id=…&a=<id>&t=<token>"`.
  A button with no `run` and no `default` uses `activationType="system" arguments="dismiss"`, so nothing is launched.
- Body: `launch="toastback://act?id=…&a=__body&t=…"` with `activationType="protocol"`, unless `on_click=none`.
- `style` → `hint-buttonStyle="Success|Critical"` (Windows 11; ignored elsewhere).
- `reminder` / `alarm` / `urgent` scenarios require ≥1 button. Validate this.
- Tag = id, group = `toastback`, so the activation handler can remove the toast after handling it.

### Dialog rendering (TaskDialogIndirect)
- Needs Common Controls v6 → embedded manifest (see §7).
- Maps: title → window title, body → main instruction, details → content, buttons → custom buttons (`TDF_USE_COMMAND_LINKS` when ≥3 buttons), icon by `scenario` or a custom icon.
- `mode: dialog` is shown by a **detached child process** (`__dialog <id>`), so the caller still returns immediately.
- Foreground: a dialog not opened by a user click may open behind other windows. Use `TDN_CREATED` → `SetWindowPos(HWND_TOPMOST)` + `FlashWindowEx`. Dialogs opened from a toast click are fine (user-initiated).
- The selected button goes through the same callback path as a toast button.

## 5. CLI

```
toastback [show] [FILE | -]          # JSON spec from file or stdin
          [-t TITLE] [-m BODY] [-d DETAILS] [-i ICON] [--mode toast|dialog]
          [--scenario …] [--id ID]
  → prints id, exit 0 | exit 2 invalid spec | exit 3 failed to show | exit 4 not installed

toastback install [--wsl DISTRO|all|none] [--add-to-path]
toastback uninstall [--purge]
toastback shim [--win-exe PATH]      # print the WSL shim to stdout
toastback doctor [--json]
toastback validate FILE...           # check specs without showing them
toastback log [-n N] [--id ID]       # tail the history
toastback remove ID | clear          # remove toasts from Action Center + pending
toastback --version                  # version + git sha

# global context flags, accepted by every subcommand (the shim always passes them)
          [--distro D] [--user U] [--cwd DIR]

# internal
toastback activate URI               # protocol handler
toastback __dialog ID                # detached dialog process
```

Quick flags and a JSON spec can be combined: flags override spec fields.
`doctor` checks: registration keys point at the installed exe, installed version vs running version,
notifications enabled for the app (`ToastNotifier.Setting`), `wsl.exe` works, shim present and current in the
calling distro (when called via the shim), state dir writable. Non-zero exit if anything is broken.

## 6. Installation & WSL shim

### `toastback.exe install` (idempotent; also the upgrade path)
1. Copy the running exe to `%LOCALAPPDATA%\toastback\bin\toastback.exe`.
   - If the target is locked (a callback is running), rename it to `toastback.exe.old` first; delete stale `.old` files on later runs.
   - Write the copy by reading bytes and writing a new file, so the browser's "downloaded from the internet" marker
     isn't carried over. Otherwise every toast click could trigger a security prompt. Print a line saying so.
     (Proper fix later: code signing.)
2. Write the embedded `icon.png` next to it.
3. Register (HKCU only):
   - `Software\Classes\AppUserModelId\Toastback` → `DisplayName=toastback`, `IconUri=<bin>\icon.png`.
     → **Verify in M0** that toasts show from an unpackaged exe with only this key. Fallback: Start Menu shortcut with
     `System.AppUserModel.ID=Toastback` (IShellLinkW + IPropertyStore).
   - `Software\Classes\toastback` → `URL Protocol=""`, `shell\open\command` = `"<bin>\toastback.exe" activate "%1"`.
4. `--add-to-path`: append `<bin>` to the user `PATH` (`HKCU\Environment`) and broadcast `WM_SETTINGCHANGE`. Off by default.
5. WSL shim (`--wsl`, default = the calling distro if known, else `all`; `none` to skip):
   for each target distro run
   `wsl.exe -d <D> -- sh -c 'mkdir -p "$HOME/.local/bin" && cat > "$HOME/.local/bin/toastback" && chmod +x "$HOME/.local/bin/toastback"'`
   with the rendered shim on stdin. Distro list: `wsl.exe -l -q` (output is **UTF-16LE** — decode it).
   Warn if `~/.local/bin` is not on that distro's PATH.
6. Write `install.json`, print a summary, show a "toastback installed" toast as a live test.

`uninstall` reverses all of it, using `install.json` (removes shims from the recorded distros, registry keys,
PATH entry, `bin\`). `--purge` also deletes logs, pending and cache.

### Shim template (embedded in the exe, rendered at install time)
```bash
#!/usr/bin/env bash
# toastback WSL shim — generated by `toastback.exe install` (shim v2, toastback {{VERSION}})
# Regenerate:  toastback install   (redirecting `toastback shim` into this file would empty it first)
TOASTBACK_WIN_EXE='{{WIN_EXE_PATH}}'
exe="${TOASTBACK_EXE:-$(wslpath -u "$TOASTBACK_WIN_EXE")}"
distro="${WSL_DISTRO_NAME:-}"
if [ -z "$distro" ]; then
  # WSL sets WSL_DISTRO_NAME only for processes it starts itself (not systemd services, cron, ...):
  # take the name from this distro's root as Windows sees it, \\wsl.localhost\<distro>\
  # (env -u: wslpath fails when the variable is set but empty)
  root="$(env -u WSL_DISTRO_NAME wslpath -w / 2>/dev/null || true)"
  root="${root%\\}"
  distro="${root##*\\}"
fi
exec "$exe" --distro "$distro" --user "$(id -un)" --cwd "$PWD" "$@"
```
- The Windows path is baked in and converted with `wslpath` at call time. This works with any automount root (`/mnt/c`, `/c`, …).
- `TOASTBACK_EXE` overrides the exe, for development only. Note that protocol activation still uses the *installed* exe.
- The exe converts Linux paths in `icon`/`image` to `\\wsl.localhost\<distro>\…` using the context, then copies them to the cache.

### `install.sh` (release asset; the WSL one-liner)
```bash
curl -fsSL https://github.com/<owner>/toastback/releases/latest/download/install.sh | bash
# pin a version:  ... | TOASTBACK_VERSION=v0.1.0 bash
```
Steps:
1. Check we're in WSL (`$WSL_DISTRO_NAME` set) and `curl` + `sha256sum` exist.
2. Find the Windows temp dir: `cd /mnt/c 2>/dev/null; cmd.exe /c 'echo %TEMP%' | tr -d '\r'` → `wslpath -u`.
   (Run `cmd.exe` from a Windows-side cwd to avoid the "UNC paths are not supported" warning.)
3. Download `toastback.exe` + `SHA256SUMS` from `releases/latest/download/` (or `releases/download/$TOASTBACK_VERSION/`)
   into that temp dir and verify the checksum. (The repo is public, so plain `curl` works.)
4. Run `"<temp>/toastback.exe" install --wsl "$WSL_DISTRO_NAME"` (the exe does everything else), then delete the temp copy.
5. Print next steps: `toastback -t hello -m world`, `toastback doctor`.

### Windows-only install
Download `toastback-x86_64.zip`, extract anywhere, run `toastback.exe install --wsl all` (or `--wsl none`), optionally `--add-to-path`.

### Upgrade / uninstall
Re-run `install.sh` or `toastback.exe install` from a newer download. Shims are re-rendered every time.
`toastback uninstall` (from WSL or Windows).

## 7. Project setup (WSL)

```bash
sudo apt install build-essential clang lld llvm just shellcheck   # see README "Dev prerequisites"

cargo install --locked cargo-xwin        # or: pip install cargo-xwin
```

- `Cargo.toml` release profile: `opt-level="z"`, `lto=true`, `codegen-units=1`, `panic="abort"`, `strip=true`.
- `#![windows_subsystem = "windows"]` in `main.rs`.
- `build.rs`: `embed-resource` (uses `llvm-rc` when cross-compiling) for `res/toastback.rc` → manifest
  (Common Controls v6, PerMonitorV2 DPI, UTF-8 code page, `asInvoker`), icon, version info.
  Also set `TOASTBACK_GIT_SHA` from `GITHUB_SHA` or `git rev-parse --short HEAD`.
- Crates: `windows` (only the features needed), `serde`, `serde_json`, `anyhow`, `clap` (derive),
  `getrandom`, `embed-resource` (build). All MIT/Apache, compatible with GPL-3.0. Ask before adding others.


## 8. CI / release (GitHub Actions)

Repo bootstrap: `gh repo create toastback --public --source . --push --description "Async Windows toasts with callbacks, for WSL and scripts"`.
Also add `.github/dependabot.yml` (weekly, `cargo` + `github-actions`).

### `.github/workflows/ci.yml` — on push to `main` and on PRs
- **build** (`ubuntu-latest`):
  install the stable toolchain + `x86_64-pc-windows-msvc` target; prebuilt `cargo-xwin` (pip or cargo-binstall,
  don't compile it in CI); `apt install clang lld llvm`; cache `~/.cargo` + `target` (e.g. Swatinem/rust-cache)

  `cargo fmt --check` → `cargo xwin clippy -- -D warnings` → `shellcheck` → `cargo xwin build --release`;
  upload `toastback.exe` as a workflow artifact.
- **test** (`windows-latest`): native `cargo test` (MSVC and Rust are preinstalled on the runner).
  Tests that need an interactive desktop (showing toasts/dialogs) are `#[ignore]` and only run manually.
- **smoke** (`windows-latest`, needs build): download the artifact and run the *cross-built* exe:
  `--version`, `validate examples/*.json`, `install --wsl none`, `doctor --json` (treat "notifications unavailable in
  this session" as a warning), `uninstall --purge`, then assert the registry keys are gone.
- Use current major versions of the actions; `permissions: contents: read`.

### `.github/workflows/release.yml` — on tag push `v*.*.*`
1. Reuse the same build + smoke jobs (a reusable workflow, or a shared composite action).
2. Fail if the tag doesn't match the `Cargo.toml` version.
3. **package** (`ubuntu-latest`):
   - `dist/toastback.exe`
   - `dist/toastback-x86_64.zip` → `toastback.exe`, `README.md`, `LICENSE`, `examples/`
   - `dist/install.sh` (from `scripts/install.sh`)
   - `dist/SHA256SUMS` over the three files above
   - Asset names have **no version in them**, so `releases/latest/download/<name>` URLs stay stable.
4. Optional, cheap: `actions/attest-build-provenance` for `toastback.exe` and the zip.
   Users can then check with `gh attestation verify toastback.exe -R <owner>/toastback`.
5. **publish**: `gh release create "$GITHUB_REF_NAME" --verify-tag --generate-notes dist/*`
   with `GH_TOKEN: ${{ github.token }}` and `permissions: contents: write` (plus `id-token: write` and `attestations: write` if attesting).

## 9. Module layout

```
src/
  main.rs        # subsystem attr, arg parsing (lexopt), global context flags, dispatch
  spec.rs        # serde types, defaults, validation, merge flags→spec
  context.rs     # distro/user/cwd, WSL→Windows path conversion, image cache
  store.rs       # state dir, pending files, tokens, pruning, jsonl log + rotation, install.json
  toast.rs       # XML builder (escaped), show, remove, ToastNotifier.Setting
  dialog.rs      # TaskDialogIndirect wrapper, topmost/flash, returns chosen button
  activate.rs    # URI parsing + token check, body/details flow, dispatch to exec
  exec.rs        # run forms → process spawn (hidden), WSLENV, timeout, capture output
  install.rs     # self-copy, registry, PATH, shim rendering + distribution, uninstall, doctor
res/             # toastback.rc, app.manifest, icon.ico, icon.png, shim.sh.tmpl
scripts/         # install.sh
examples/        # *.json, one per feature
docs/            # decisions/, manual-test.md
.github/workflows/  # ci.yml, release.yml
justfile
```
Keep `unsafe` inside `toast.rs`, `dialog.rs`, `exec.rs`, `install.rs`, behind small safe functions.

0. Bootstrap: `git init`, `cargo init --name toastback`, `rust-toolchain.toml`, `.cargo/config.toml`, `justfile`,
   `LICENSE` (GPL-3.0 text), `README.md` stub, `.gitignore`, and a `CLAUDE.md` with the locked decisions (§2)
   and the working agreement (§13). Create the public GitHub repo with `gh` and push.
   Placeholder icon: a simple generated bell/toast glyph as `icon.png` (256 px) + multi-size `icon.ico`,
   made by a small script. I'll replace it later.
1. Cross-build a GUI-subsystem exe with an embedded manifest and icon via `just build`; run it from WSL.
2. From WSL: `id=$(toastback.exe …)` captures stdout; stderr is visible; exit code propagates.
3. A toast shows with only the registry AUMID (no shortcut). If not, implement the shortcut fallback.
4. A protocol-activated button launches `toastback.exe activate "<uri>"` with no console flash.
5. TaskDialog shows with custom buttons (manifest works).
→ Record results in `docs/decisions/000-spikes.md`. **Accept:** all five work, or fallbacks are chosen.

### M2 — Dialogs (~3 h)
`mode: dialog` via detached `__dialog`, `on_click: details` from a toast body, topmost/flash handling, shared callback path.
**Accept:** `toastback --mode dialog -t "Reboot?" …` returns instantly; the dialog appears on top; choosing a button
runs its callback. Clicking a toast body with `details` opens the details dialog, and its buttons work.

`notify_on_error` error toast, `doctor`, `validate`, `log`, `remove`/`clear`, pending pruning, callback `timeout`,
`--add-to-path`, `--wsl all`, README (bash / pwsh / Task Scheduler examples), `examples/*.json`.
**Accept:** `docs/manual-test.md` passes on Windows 11 x64 (and Windows 10 if available).

`ci.yml`, `release.yml`, `scripts/install.sh`, `just release`.
**Accept:** a PR runs build + test + smoke green; `just release 0.1.0` produces a GitHub release with the four assets;
on a clean distro (e.g. a fresh `wsl --install -d Ubuntu --name tb-test`), the curl one-liner installs it,
and `toastback -t hi -m there` shows a toast whose button callback runs in that distro.

## 11. Gotchas to keep in mind
- Toasts can't be shown from Session 0. Scheduled tasks must run as the user, "only when user is logged on".
- Focus Assist / Do Not Disturb suppresses toast banners (they still land in Action Center). Use `mode: dialog` or `scenario: alarm` for must-see prompts. `doctor` reports if notifications are disabled for the app.
- GitHub-hosted Windows runners may not be able to show toasts at all. Keep display out of CI assertions.
- The first `wsl.exe` call when the distro is stopped can take several seconds. Callbacks run in the activation process, which simply waits. Nothing blocks the user.
- `WSL_DISTRO_NAME` is not visible to Windows processes, so the shim must pass the context.
- `wsl.exe -l -q` prints UTF-16LE with possible NULs/BOM. Decode it properly.
- `bash -lc` loads the login profile, so PATH is the user's real one. `--exec` doesn't, so document that difference.
- Re-installing while an activation process is running: the exe is locked. Rename it to `.old` and copy the new one.
- Unsigned downloaded exes: SmartScreen may warn on first run from a browser download. The curl/gh path doesn't set the download marker. Document it in the README.
- Max 5 buttons. Images: local PNG/JPG, keep them small (<200 KB, ≤1024 px).
- Toast and dialog text is UTF-16 internally. JSON from WSL is UTF-8. Test with Hungarian accents (őű) and emoji.
