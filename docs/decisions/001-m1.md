# 001: M1 implementation choices

Date: 2026-10-14. Where M1 deviates from or fills gaps in PLAN.md.

## Callbacks

- **`wsl.exe … --exec bash -lc "<string>"`, not `-- bash -lc`** (§4 table). With `--`, wsl.exe hands the rest of
  its command line to the user's login shell, which parses it a second time and mangles quotes and `$`. With
  `--exec`, the argv arrives as is. Tested with spaces, `"`, `'`, `$`, `&` and UTF-8, and the shell form
  still loads the login profile through `bash -l`.
- **`pwsh` runs with `-EncodedCommand`** (base64 of UTF-16LE), so PowerShell's command-line quoting never applies.
  If `pwsh.exe` isn't found, `powershell.exe` runs instead.
- **`cmd` uses `cmd.exe /d /s /c "<string>"`**, appended verbatim (`raw_arg`). cmd.exe doesn't follow the MSVC argv
  rules, so Rust's quoting would corrupt the string.
- **Windows forms run in `%USERPROFILE%`** unless the run sets `cwd`. A WSL `cwd` in a run is converted like an
  image path (`/mnt/c/x` → `C:\x`).
- **A timeout kills `wsl.exe`, and that ends the Linux process too.** Checked: no orphaned `sleep`.
- **A notification handles one click.** After its callback, the pending file is marked `done`, and later
  activations (a replayed URI, a second click) are logged as `rejected: already handled`.

## Spec and CLI

- **A context written in the spec wins over the shim's `--distro/--user/--cwd`.** The shim always passes them, so
  otherwise a spec could never choose its own context. The quick flags (`-t`, `-m`, …) still override spec fields.
- **`show` is the default command.** If the first argument after the context flags isn't a subcommand, `show` is
  inserted. (clap's `args_conflicts_with_subcommands` broke `--distro D install`, the shim's form.)
- **Spec file paths from WSL** (`toastback examples/deploy.json`) are resolved like image paths, against the
  caller's cwd.
- `validate` and `notify_on_error` are planned for M3. The spec field is parsed and validated already.

## Install

- **`install.json` records `shims: [{distro, user}]`**, not just distro names. The calling distro gets the calling
  user's shim, and `uninstall` removes it from the same place.
- **Uninstall only deletes a shim that carries the `# toastback WSL shim` marker.** When the running exe is
  inside the directory being deleted, a detached `cmd.exe` removes the directory once the process has exited.
- **The PATH check** runs the user's login shell (`$SHELL -lc`), so zsh users with PATH in `.zshenv` aren't warned
  for no reason.

## Pulled forward from M3

`log` (needed for M1's acceptance), pending pruning on every run, callback `timeout`, `--wsl all`
(UTF-16 `wsl -l -q` decoding, or UTF-8 with `WSL_UTF8=1`).
