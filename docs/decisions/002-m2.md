# 002: M2 dialogs

Date: 2026-10-14. All of M2's acceptance criteria were checked by hand on Windows 11 (build 26300).

- **Mapping:** title → window title, body → main instruction (the title again when there's no body), details →
  content. Buttons become custom TaskDialog buttons, shown as command links when there are 3 or more. Without
  buttons, the dialog gets a plain **Close** button. Esc, X and Close all count as "closed", with no callback.
- **Icon:** `alarm`/`urgent` show the warning icon, everything else the information icon. The window/taskbar icon is
  the exe's bell (resource 1, set via `WM_SETICON`). Custom `icon` images aren't shown in dialogs: TaskDialog
  needs an HICON, and loading PNGs would take WIC. It can be added later if it's wanted.
- **On top:** on `TDN_CREATED` the dialog is made `HWND_TOPMOST` and asks for the foreground. If Windows
  refuses (the dialog wasn't started by a click), the taskbar button flashes. Checked: the dialog stays on top while
  another window has focus.
- **Detached `__dialog <id>`:** `show` starts it with `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`, and with
  `CREATE_BREAKAWAY_FROM_JOB` when the caller's job allows it. Before spawning, `show` marks its own std handles
  as non-inheritable. Otherwise the child could hold WSL interop's pipes open, and the WSL side would wait for
  the dialog. Measured: `toastback examples/reboot-dialog.json` returns in 0.19 s.
- **One callback path:** a toast button, a body click (`default` or the details dialog) and a dialog-mode choice
  all end in the same `finish` → `run_callback`. The log shows `dialog_shown` and `dialog_closed` (with the chosen
  button, or `(closed)`), then the usual `callback_*` events.
