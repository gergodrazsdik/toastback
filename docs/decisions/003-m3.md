# 003: M3 polish, plus click feedback and toastback-cli.exe

Date: 2026-10-14.

## Two binaries from one crate

The crate is now a library (`src/lib.rs`, `toastback::main()`) with two thin binaries:

- `toastback.exe` (`src/main.rs`, GUI subsystem): the protocol handler, the dialog process and the WSL shim's
  target. Windows never opens a console window for it.
- `toastback-cli.exe` (`src/bin/toastback-cli.rs`, console subsystem): for interactive cmd/PowerShell. They don't
  wait for GUI programs (output after the prompt, no `$LASTEXITCODE`), see 000-spikes.md. This is the fallback
  PLAN.md §3 names, added at the user's request.

Both get the same resources (`embed-resource` links them into every bin). `install` copies both, and registration
always points at `toastback.exe`. A dialog started from `toastback-cli.exe` runs under its sibling
`toastback.exe` (`install::gui_exe`). `console.rs` now also clears `DISABLE_NEWLINE_AUTO_RETURN` on a console the
process already owns, so the CLI exe doesn't print a staircase in a WSL terminal either.

**Release impact (M4):** `toastback-cli.exe` goes into the zip (and should be a separate asset).
`install.sh` only needs `toastback.exe` for WSL use, but should install both so `--add-to-path` users get the CLI.

## Click feedback: `notify_on_success`

A new spec field, default `false`. On success it shows "<button label>: done" with the notification title,
the duration and the last line of stdout. `notify_on_error` (default `true`) shows "<label>: failed" with the
exit code / timeout / start error and the last line of stderr (or stdout). Feedback toasts have no buttons
and no body action, and never ask for feedback themselves. They're built by `activate::feedback`, which is pure
and tested on the host.

## Commands

- `validate FILE...`: the same loading as `show` (context, flags, validation), plus a check that `icon`/`image`
  can be read. Exit 2 if any file fails. `just test` runs it on `examples/*.json` through the Windows exe.
- `remove ID...`: removes the toast from Action Center and deletes the pending file, so its buttons stop working.
  A dialog that is already open for that id runs nothing when answered: `finish` reloads the pending file first.
  Exit 1 if an id is unknown. `clear` does the same for all.
- `doctor [--json]`: install record, exe, app id, protocol command (it must point at the installed exe),
  notification setting (`Setting` errors before the first toast: a warning, not a failure, see 000-spikes.md),
  user PATH (if `--add-to-path` was used), `wsl.exe`, the calling distro's shim (byte-compared with what `install`
  would write), and that the state dir is writable. Exit 1 on any failure. Warnings don't count.
- `install --add-to-path`: appends `bin\` to `HKCU\Environment\Path` (keeping it `REG_EXPAND_SZ`, matching
  case-insensitively and ignoring a trailing `\`) and broadcasts `WM_SETTINGCHANGE`. `uninstall` removes it again
  if `install.json` says it added it.

## Smaller changes

- The registry code moved to `registry.rs` (`get_string`, `set_string`, `delete_tree`, `key_exists`).
- `open` targets get `%VAR%` expanded (`ExpandEnvironmentStringsW`); ShellExecute doesn't do that itself.
- A relative path with no caller context (run without the shim) is used as is, relative to the process's cwd.
  Before, it was an error. This lets `toastback.exe validate examples/*.json` work straight from WSL.
- Validation messages name enum values in their JSON spelling (`"alarm"`, not `Alarm`).
