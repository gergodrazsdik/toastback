# 004: M4 CI and release

Date: 2026-10-14. v0.1.0 was released (unsigned) to test the whole process.

## What CI caught

- **CRLF checkouts:** the Windows runner checks out with `core.autocrlf`, so `include_str!` embedded a CRLF
  shim template, and a CRLF bash script doesn't run in WSL. `.gitattributes` pins LF (`* text=auto eol=lf`), and
  `render_shim` strips `\r` as well. Linux-built releases were never affected.
- `doctor` reported `wsl.exe ok` with an empty distro list on the runner. It's a warning now.

## The `curl | bash` installer swallowed itself

The v0.1.0 one-liner did nothing: no output, exit 0. Piped into bash, the script *is* bash's stdin. The first
`cmd.exe` call (finding `%TEMP%`) inherited that stdin through WSL interop and read the rest of the script, so
bash hit end-of-input. Local tests ran `bash scripts/install.sh` from a file and couldn't catch it.

Fix: everything is in `main()`, called on the last line, so bash parses the whole script first. A truncated
download is then a syntax error that runs nothing. Windows commands also get `</dev/null`. Test the installer piped
from now on: `cat scripts/install.sh | TOASTBACK_BASE_URL=file://<dir> bash`.

The fixed `install.sh` ships with the next release. Until then it can be run from main:
`curl -fsSL https://raw.githubusercontent.com/gergodrazsdik/toastback/main/scripts/install.sh | bash`
(it still downloads the v0.1.0 release exes).

## Smart App Control, again

On this machine (Smart App Control enforcing):

| Exe | Started from | Result |
|---|---|---|
| local dev build, copied by WSL `cp`/`curl` | `C:\Users\…`, `%TEMP%` | blocked ("An Application Control policy has blocked this file") |
| local dev build | the WSL filesystem, or `bin\` written by `install` | runs |
| CI-built v0.1.0 release, downloaded by `gh`/`curl` | `%TEMP%` (`install.sh`) | **runs** |

Why the release build passes is unknown. It may have a reputation in Microsoft's cloud lookup that a fresh local
build doesn't. The README now says Smart App Control *may* block unsigned builds. Code signing remains the real fix.

## Release process notes

- `just release VERSION`: the clean-tree check ignores untracked files (the sandbox's placeholder files), and the
  commit is skipped when `Cargo.toml` is already at that version.
- The network to api.github.com dropped out repeatedly during this session. The release workflow itself was
  unaffected, but `gh run watch` at the end of `just release` failed. Re-run
  `gh run watch <id>` or check the Actions tab.
- Verified on v0.1.0: all assets match `SHA256SUMS`, ClamAV clean, and `gh attestation verify toastback.exe -R
  gergodrazsdik/toastback` names `release.yml@refs/tags/v0.1.0`.
